The repo is genuinely production-grade for an open-source MCP server. The
remaining notes are documentation drift between long-running files
(CONTRIBUTING / HANDOFF / CHANGELOG), one disclosed schema gap on
`airbnb_search` (rating / review_count are returned but not in the Zod output
schema — already documented in the tool doc), and a single deliberate `TBD`
string in a fixture (also documented).

Nothing in this list would embarrass at an Airbnb engineering review. The
honesty section in the README and the `_mock: true` / `_pitch` envelope on
demo tools defuse the only review concern (mock vs live).

## Notes for future improvement (not blocking)

1. **`airbnb_search` Zod output schema** does not list `rating` / `review_count`
   even though the parser emits them. Either tighten the schema to include
   them as `.optional()` or use `.passthrough()` on the per-result object.
   Currently disclosed in the tool doc, so honesty is intact, but a tighter
   schema removes one question an Airbnb reviewer will ask.

2. **`CONTRIBUTING.md` §"How to add a new tool"** says tests collocate with
   the tool folder. Reality: tests live in `tests/unit/`, fixtures in
   `src/mocks/`. One paragraph correction.

3. **`CHANGELOG.md` [0.1.0-alpha.1]** header is dated `2026-05-04`. The
   actual release/tag/live-smoke happened `2026-05-20`. Update the date so
   it lines up with the smoke artifact filename.

4. **README claims "170+ commits"** — actual 180. Either round-trip update,
   or change to "180+" (cosmetic).

5. **No `docs/README.md` top-level index.** Not strictly needed (flat tree)
   but `tree docs/` or a one-line index would help cold readers find ADRs
   vs pitch vs tool docs.

6. **`.changeset/`** has no in-flight changesets. The CHANGELOG notes this
   was an intentional manual override of the auto-bump. After public-flip,
   onboard new releases via `npx changeset add` to restore the changeset
   audit trail.

## Most surprising finding

**The repo is more honest about its limitations than most production OSS.**
The `_mock: true` / `_pitch` envelope on demo tools, the README "Honesty
section — what this is NOT", the deliberate `Cleaner: TBD` string surfaced
to the user rather than auto-filled, the `airbnb_search` doc explicitly
flagging its own Zod schema gap — this is exactly the posture an Airbnb
trust & safety reviewer wants to see. It's far rarer than it should be.

The least surprising-but-still-impressive finding: a fresh stdio call
against `dist/index.js` returns **real Berlin listings with real prices in
EUR and real review counts**, end-to-end, in under 7 seconds. The live
path is not theoretical.
